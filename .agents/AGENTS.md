# Project Rules for Backend Developer Clarity

## Git & File Change Documentation Rule
Whenever changes are made, staged, or pushed:
1. Provide a detailed, file-by-file breakdown of what changed in each file.
2. Highlight data model changes, mock data fallbacks, API signatures, timestamp calculations, or state structures so that the backend developer can easily understand the requirements for actual API integration.
3. Keep commit messages and summary reports clear, structured, and developer-friendly.

## Build Execution Rule
Do NOT run `npm run build` or automated build verification commands unless explicitly requested by the user.
